1. VERR_VM_DRIVER_VERSION_MISMATCH
![alt text](<화면 캡처 2025-11-03 112927.png>)

- 현재 설치된 VirtualBox 프로그램의 버전과 시스템에 설치된 VirtualBox 커널 드라이버(support driver)의 버전이 서로 일치하지 않기 때문에 발생

- 해결방법: VirtualBox 완전히 제거하기
Windows:
제어판 > 프로그램 > 프로그램 및 기능으로 이동하여 VirtualBox를 찾아 제거합니다.
제거 후에도 남아있을 수 있는 설치 폴더(C:\Program Files\Oracle\VirtualBox)와 설정 폴더(C:\Users\사용자이름\.VirtualBox)를 수동으로 삭제합니다. (주의: 가상 머신 이미지(.vdi 파일)는 다른 곳에 백업해두세요.)

2.VERR_SUP_VP_NOT_SIGNED_WITH_BUILD_CERT
![alt text](<화면 캡처 2025-11-03 113607.png>)

오류의 원인
이번 오류의 핵심은 VERR_SUP_VP_NOT_SIGNED_WITH_BUILD_CERT 입니다.

오류 메시지 해석: "VirtualBox의 나머지 부분과 동일한 인증서로 서명되어야 하는 이미지가 서명되지 않았습니다."
쉬운 설명: VirtualBox를 실행하는 데 필요한 중요 파일(VirtualBoxVM.exe 또는 관련 드라이버 VBoxDrvStub)의 디지털 서명이 손상되었거나, 보안 프로그램에 의해 차단되어 VirtualBox가 '이 파일은 우리가 만든 정품이 아니다'라고 판단하고 실행을 거부하는 상황입니다. 이는 보안을 위한 정상적인 방어 동작입니다.
주요 원인은 다음과 같습니다.

백신 또는 보안 소프트웨어의 간섭 (가장 흔한 원인): 많은 보안 프로그램이 시스템 깊숙이 접근하는 VirtualBox의 드라이버를 잠재적인 위협으로 오인하여 차단하거나 격리할 수 있습니다.
Windows 보안 기능과의 충돌: Windows의 "코어 격리(메모리 무결성)" 기능이나 "Hyper-V" 기능이 활성화되어 있으면 VirtualBox와 같은 다른 가상화 소프트웨어의 드라이버 로딩을 방해할 수 있습니다.
불완전한 설치 또는 권한 부족: 관리자 권한 없이 설치하거나 실행했을 경우, 필요한 드라이버가 시스템에 제대로 등록되지 못했을 수 있습니다.
해결 방법
가장 가능성이 높은 순서대로 아래 해결 방법들을 시도해 보시기 바랍니다.

해결 방법 1: 보안 소프트웨어(백신) 예외 처리 또는 비활성화
가장 먼저 시도해 볼 방법입니다.

사용 중인 백신, 안티바이러스, 방화벽 등 모든 보안 소프트웨어를 일시적으로 비활성화합니다.
VirtualBox를 관리자 권한으로 실행 (VirtualBox.exe 파일을 마우스 오른쪽 클릭 -> '관리자 권한으로 실행')하여 가상 머신을 시작해 보세요.
만약 문제가 해결된다면, 보안 소프트웨어 설정에서 VirtualBox 설치 폴더(보통 C:\Program Files\Oracle\VirtualBox)를 검사 예외 또는 신뢰하는 항목으로 추가한 후, 보안 소프트웨어를 다시 활성화하세요.
해결 방법 2: Windows '코어 격리(메모리 무결성)' 기능 끄기
이 기능은 서명되지 않았거나 오래된 드라이버를 차단하므로 VirtualBox와 충돌을 일으키는 주요 원인 중 하나입니다.

Windows 시작 버튼 -> 설정 -> 업데이트 및 보안 (또는 개인 정보 및 보안) -> Windows 보안으로 이동합니다.
장치 보안을 클릭합니다.
코어 격리 세부 정보를 클릭합니다.
메모리 무결성 옵션을 **끔**으로 변경합니다.
변경 사항을 적용하려면 컴퓨터를 재부팅해야 합니다.
재부팅 후 VirtualBox를 다시 실행해 보세요.
해결 방법 3: Hyper-V 기능 비활성화
Windows의 내장 가상화 플랫폼인 Hyper-V는 VirtualBox와 동시에 사용할 수 없습니다.

제어판 -> 프로그램 -> Windows 기능 켜기/끄기로 이동합니다.
목록에서 **Hyper-V**를 찾아 체크를 해제합니다.
추가로 Windows 하이퍼바이저 플랫폼과 가상 머신 플랫폼 항목도 체크 해제하는 것이 좋습니다.
확인을 누르고 컴퓨터를 재부팅합니다.
이 방법들을 순서대로 시도해 보시면 대부분의 경우 문제가 해결될 것입니다. 만약 위 방법으로도 해결되지 않는다면, 이전에 안내해 드린 것처럼 VirtualBox를 완전히 삭제하고 최신 버전을 다운로드하여 반드시 '관리자 권한으로' 재설치해 보시는 것을 권장합니다.

- 2번 방법으로 해결했으나, 보안에 영향을 줄수 있으므로, virtualBox 실행 종료후 다시끄기

3. [drm] *ERROR* vmwgfx seems to be running on an unsupported hypervisor.
 ![alt text](<화면 캡처 2025-11-03 115015.png>) 

- 원인

우분투(게스트 OS)가 "나는 지금 VMware라는 가상 환경에서 실행되는 줄 알고 VMware 전용 그래픽 드라이버(vmwgfx)를 사용하려고 해"라고 말하고 있습니다. 하지만 실제로는 Oracle VirtualBox라는 다른 가상 환경에서 실행되고 있기 때문에, 이 드라이버가 호환되지 않아 오류를 일으키고 부팅을 멈춘 것입니다.
- 해결 방법

가장 확실하고 간단한 해결 방법은 가상 머신의 그래픽 컨트롤러 설정을 변경하는 것입니다. 아래 단계를 그대로 따라 해 주세요.

가상 머신 완전히 종료하기
현재 실행 중인 우분투 창을 닫습니다. 창을 닫을 때 '저장 상태'가 아닌 **'가상 머신의 전원 끄기'**를 선택하여 완전히 종료해야 합니다.
VirtualBox 관리자에서 설정 열기
VirtualBox 메인 창에서 해당 우분투 가상 머신을 선택한 후, 상단의 '설정' 버튼을 클릭합니다.
디스플레이 설정 변경하기
설정 창 왼쪽 메뉴에서 **'디스플레이'**를 선택합니다.
'화면' 탭에서 '그래픽 컨트롤러' 항목을 찾습니다.
현재 아마 VMSVGA로 설정되어 있을 것입니다. 이 설정을 **VBoxSVGA**로 변경해 주세요.
설정 저장 및 재부팅
'확인' 버튼을 눌러 설정을 저장합니다.
이제 가상 머신을 다시 '시작' 버튼을 눌러 부팅합니다.
